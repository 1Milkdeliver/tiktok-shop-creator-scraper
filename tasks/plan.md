# 五个独立达人采集软件拆分计划

## 已确认目标

将现有多平台桌面软件拆为五个可以独立安装、独立运行、独立保存数据的软件：

1. TikTok Shop 达人采集
2. Instagram 达人采集
3. YouTube 达人采集
4. X 达人采集
5. TikTok 达人采集

现有 `tiktok-shop-creator-scraper-code` 保持原样，作为可回退的源项目；拆分过程不删除、不移动其中任何代码、数据或测试结果。

## 目标目录与产品边界

将在 `C:\Users\Huawei\Documents\ChatGPT\桌面游戏` 下建立以下五个同级项目：

| 项目目录 | 桌面软件 | 保留能力 | 独立内容 |
|---|---|---|---|
| `tiktok-shop-creator-scraper` | TikTok Shop 达人采集 | 店铺 Cookie、站点/类目/名单采集 | 应用 ID、设置、SQLite、日志、导出 |
| `instagram-creator-scraper` | Instagram 达人采集 | 公开发现、定向主页、可选本地会话、Hiker 配置 | 应用 ID、设置、SQLite、日志、导出 |
| `youtube-creator-scraper` | YouTube 达人采集 | 无需授权的关键词/频道发现 | 应用 ID、设置、SQLite、日志、导出 |
| `x-creator-scraper` | X 达人采集 | 本地账号池导入、关键词采集 | 应用 ID、设置、SQLite、日志、导出 |
| `tiktok-creator-scraper` | TikTok 达人采集 | TikTok 适配器与现有可用采集链路 | 应用 ID、设置、SQLite、日志、导出 |

每个项目仅显示自己的任务、连接配置、达人库与日志；不保留平台切换器、跨平台统计或跨平台任务监控。

## 实施顺序

### 阶段 1：可独立运行的基础工程

1. 从现有项目复制通用桌面壳、数据库、导出、日志和打包配置到五个新目录。
2. 为每个项目设定唯一的产品名、`appId`、Windows 快捷方式、数据目录和 SQLite 文件名，确保安装或运行互不覆盖。
3. 将平台目录收缩为单平台，删除 UI 中的平台选择、跨平台概览和其他平台 IPC 入口。
4. 将共享辅助代码直接内置到各自项目；第一阶段不增加第六个共享运行时或共享数据库依赖。

### 阶段 2：逐个平台纵向切片

1. TikTok Shop：保留现有正式采集与本地库工作流。
2. Instagram：保留公开发现、定向抓取、本地会话/浏览器采集、日志和独立持久化；不包含任何绕过验证或规避风控能力。
3. YouTube：保留现有本地 Python 发现/采集链路与无授权界面。
4. X：保留本地账号池导入与现有采集链路。
5. TikTok：保留当前适配器；若当前仅有测试适配器，会明确标为“开发预览”，不伪称可生产采集。

### 阶段 3：独立验证

对每一个新项目分别执行：

1. 自动化测试与静态检查。
2. 应用启动检查。
3. 本地 SQLite 隔离检查。
4. UI/IPC 检查：不能调用其他平台的入口，也不能展示其他平台的任务或日志。
5. Windows 安装包元数据检查。

## GitHub 远程仓库

本阶段只创建本地独立项目和本地 Git 初始化。创建 GitHub 仓库、设置可见性、远程地址和推送属于外部发布动作，待你确认以下信息后单独执行：

- GitHub 账号或组织；
- 五个仓库是否公开；
- 是否使用上表默认仓库名；
- 是否迁移原项目的提交历史（默认不迁移，五个仓库从清晰的初始提交开始）。

## 验收标准

- 五个软件可以同时安装与运行，数据、日志、设置和数据库不互相读取。
- 每个软件只存在一个平台的名称、采集目标、授权入口和达人库。
- 原多平台项目以及现有用户数据不受修改或删除。
- 每个新项目都有独立 README、测试命令和打包配置。

## 风险与处理

| 风险 | 处理方式 |
|---|---|
| 当前项目存在未提交的用户改动 | 只读取并复制源文件；不重置、不整理、不覆盖源工作区。 |
| 五个平台成熟度不同 | 保留真实实现状态；不把 fixture 或预览链路标成生产能力。 |
| 同时安装造成数据串库 | 为每个软件设置独立 Electron `appId` 与明确的数据目录/数据库文件。 |
| GitHub 发布权限不明确 | 不创建远程仓库、不上传内容，直到获得账号、可见性和命名确认。 |
